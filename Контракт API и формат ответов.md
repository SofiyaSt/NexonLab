# Пояснение: контракт API и формат ответов

Контракт API задаёт единые правила запросов и ответов для клиентских приложений. Клиент должен предсказуемо понимать результат, ошибки и способ получения длинных списков.

## Ошибки

Ответ об ошибке должен содержать стабильный машинный код, краткое сообщение для клиента и технический идентификатор запроса для диагностики. Детали реализации, секреты и лишние персональные данные клиенту не возвращаются. Клиент принимает решения по коду ошибки, а не пытается разбирать свободный текст.

## Пагинация

Длинные списки выдаются частями с параметрами, например `limit` и `offset` либо курсором. Ответ сообщает, есть ли следующая часть или возвращает курсор продолжения. Максимальный размер страницы ограничивается сервером.

## Фильтрация и сортировка

API явно перечисляет поддерживаемые поля и значения фильтрации и сортировки. Клиент не должен передавать произвольные имена полей, SQL-фрагменты или выражения. Фильтры применяются с учётом прав пользователя, а не расширяют доступ.

Названия полей, формат дат, поведение пагинации и структура ошибок фиксируются в версионируемой документации API Nexon Registry.
