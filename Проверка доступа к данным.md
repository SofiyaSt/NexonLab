# Пояснение: проверка доступа к данным

Проверка доступа должна отвечать на два вопроса: **что пользователь может делать по своей роли** и **с каким конкретно объектом он может это делать**.

Например, роль пациента может разрешать просмотр записей, но пациенту доступна только его собственная запись. Роль врача может разрешать просмотр расписания, но только в назначенных клиниках и в пределах его врачебной практики. Одной проверки факта входа или наличия роли недостаточно.

Проверка выполняется на сервере при каждом запросе, включая чтение, изменение и скачивание документов. Идентификатор объекта из URL или тела запроса не считается доказательством права доступа. Если права нет, сервер не раскрывает чужие сведения и возвращает предусмотренный API отказ.

Права выдаются по принципу минимально необходимых полномочий. Важные обращения к чувствительным данным и изменения фиксируются в аудите согласно требованиям ТЗ.
